# Changelog

All notable changes to SynapseCitySOS are documented here. Entries follow the
Keep a Changelog format and version tags use Semantic Versioning.

## [Unreleased] - 2026-11-07

### Fixed
- Console UI audit: added a mounted emergency-event creation route, enabled
  the “Gần tôi” filter to request geolocation, escaped Leaflet popup text,
  rendered AI text without raw Markdown, removed product/architecture scope
  copy from operator/citizen screens, translated phase-board labels, fixed
  the footer About/contribution links, and localized the event-resolution
  note.

## [Unreleased] — Tier-2 AI, event feed and ETag integration
### Added
- **AI situation panel**: the public map calls `POST /v1/ai/brief` for a
  grounded 24-hour brief with source citations and `POST /v1/ai/ask` for
  knowledge-base RAG answers. Both use the published Tier-2 SDK
  (`@synapsedx/capabilities@^0.5.1`); no Tier-1/model key exists in SOS.
- **Live KTTV hazard feed**: the public map reads
  `@synapsedx/capabilities@0.4.0` `hazards.today` through a 30-second
  read-through cache and merges it into `/v1/hazards`, `/v1/hazards/recent`
  and the geo queries. Crawler status is projected into
  `/v1/hazards/ingest/status`.
- The map panel now shows **"Cảnh báo thiên tai hôm nay"** with the
  NCHMF/VNDMS source and the last successful update time.

### Security
- `AUTH_SECRET` must be set in production: the service fails fast instead of
  silently generating an ephemeral session secret.
- Rate limiting trusts the last `X-Forwarded-For` hop appended by the edge.
- The console CSP now matches the app: Google Fonts and the pre-paint boot
  script are allowed (previously blocked, breaking fonts/splash), while
  external script origins stay `'self'`.
- Public gateway ports are bound to 127.0.0.1; the gateway sanitizes echoed
  correlation IDs.


### Added

- CI hardening: CodeQL, dependency review on pull requests, actionlint,
  CycloneDX SBOM artifact, npm audit gate, Dependabot, PR template and
  concurrency controls. Tier-2 HITL adoption is tracked in issue #24.

### Fixed

- **Live admin login.** Production returned `403 demo_auth_disabled` because SOS
  had no Tier-2 identity adapter. `/v1/auth/*` now verifies email/password with
  the Tier-2 auth capability (`SOS_AUTH_MODE=tier2`, the default); login,
  registration, refresh, logout, `me` and password change call the
  `@synapsedx/capabilities` `auth` namespace (with an optional delegated
  `exchange`). The Tier-2 access/refresh token is stored inside the signed SOS
  session and never returned to the browser.
- Roles are server-assigned: a verified account is a `responder`;
  `SOS_BOOTSTRAP_ADMIN_EMAILS` (comma-separated) grants `admin`; registration
  through Tier-2 creates a responder account (or `admin` for a bootstrap email).
  A client-supplied `role` is ignored and `SOS_AUTH_DEFAULT_ROLE=admin` is not
  honoured.
- The console login/register/profile screens now use **email** (with
  backward-compatible `username` accepted only when it is an email); the
  password-change screen reports Tier-2 success/failure honestly.
- Demo auth now also requires `SOS_AUTH_MODE=demo`; `NODE_ENV=production`
  refuses to start with `SOS_AUTH_MODE=demo` or `ALLOW_DEMO_AUTH=true`, and the
  demo login route stays refused in production.

### Changed

- EOP drafts are generated by the Tier-2 AI capability (`ai/chat`) with
  provenance (`generated_by`, `model`, `prompt_version`, `usage`). An
  unavailable AI returns a typed `503 ai_capability_unavailable` and writes no
  plan; `{"fallback":"deterministic"}` is the only way to get the labelled
  deterministic draft. `force_new_version` is serialised per event.
- The hazard stream consumes the Tier-2 event feed with `Last-Event-ID` resume
  and only falls back to a 30 s snapshot poll when the feed is unavailable.
- `/v1/hazards/ingest/status` reports the Tier-2 scheduled VNDMS connector
  (job, schedule, last run, last success) and flags an unavailable jobs API.
- `/v1/ai/status`, `/v1/ai/chat` and `/v1/emergency/sosconn/status` proxy the
  real Tier-2 AI capability.

### Fixed

- Record reads expose `ETag`/`x-record-version`; updates send `If-Match` and
  return `409 record_version_conflict` instead of losing a concurrent update.
- Gateway forwards `If-Match`, `If-None-Match`, `Last-Event-ID` and returns the
  record-version headers.
- Metrics add Tier-2 conflict, EOP source and stream-transport counters.
- Public map labels every non-terminal status correctly; terminal events are
  filtered client-side as well.

## [0.2.0] - 2026-11-04

Audit remediation for issues #10–#21.

### Fixed

- Hazard list filters now interpret `active_only`/`is_active` as booleans
  against `is_active`; `hours` on `/v1/hazards/recent` is enforced.
- Dependency outages no longer render as safety: SSE emits a named `error`
  event, keeps the last good snapshot, and the public map shows a degraded
  banner instead of "Khu vực bạn hiện an toàn".
- `/v1/hazards/geo/near` and `/in-polygon` validate input and use real
  haversine/point-in-polygon predicates with paging and distance sorting.
- VNDMS live data uses one flat wire schema; ingestion is a validated push
  endpoint with run history and honest `unconfigured/ready/degraded/stale/error`
  status.
- EOP drafts are event-specific, versioned, idempotent and labelled
  `deterministic-fallback`; `force_new_version` increments instead of creating
  duplicate v1 plans.
- EOP submit creates idempotent pending dispatch orders; dispatch optimize
  actually assigns compatible available units with ETA and stale flags.
- AAR KPI/timeline are computed from event/dispatch/SITREP/resource records;
  resolve creates exactly one draft AAR; SITREP validation and publication
  lifecycle are enforced.
- Auth is demo-gated and fails closed; client-supplied roles are ignored; route
  authorization now enforces `emergency:read/write/dispatch/eop`.
- Tokens are no longer accepted from a query string, persisted in localStorage
  or cached for biometric replay; the console uses sessionStorage and CSP.
- Hazard deploy is idempotent; approvals require an existing usable resource
  unit; a stale `if_version` returns 409; only a 409 create conflict is retried
  as an update; `expire-stale` pages through all records.
- Gateway enforces upstream timeouts (504), proxies console bytes binary-safely,
  handles HEAD, and exposes structured logs plus `/metrics`.
- Phase boards now load real SOS data (resources, dispatch, SITREP, AAR);
  public "Nơi trú ẩn gần" queries shelter resource units by radius.
- `/health`, `/ready`, `/v1/emergency/health` report per-dependency state;
  AI endpoints return `503 capability_unavailable` instead of static answers.

### Added

- `sos-hazard-ingest-runs` dataset for VNDMS run history.
- `POST /v1/hazards/ingest`, `GET /v1/hazards/ingest/status`,
  `POST /v1/hazards/geo/in-polygon`,
  `GET /v1/emergency/resources/shelters/near`,
  `GET /v1/emergency/public/status`, `GET /v1/emergency/health` and `/metrics`.
- Rate limiting for auth, stream, geo and AI routes, plus nginx edge limits,
  token-free access logs and HSTS/CSP/referrer headers.
- Tests for filters, geo, VNDMS, EOP, dispatch optimize, AAR KPI, SITREP
  validation, role escalation, dependency failure, SSE error frames, binary
  proxying and gateway timeouts.

### Known dependencies (still open)

- Published `@synapsedx/capabilities` package (currently a workspace `file:`
  dependency).
- Tier-2 event subscription (SSE currently bounded polling with explicit
  degraded state).
- Tier-2 AI capability for real EOP/chat generation.
- Tier-2 spatial/aggregate query (SOS pages then filters in memory).
- Tier-2 conditional updates/ETags and scheduled VNDMS ingestion.

## [Unreleased] - 2026-11-03

### Changed

- Split SynapseCitySOS from SynapseCity. SOS now owns only emergency
  operations: hazard feeds including VNDMS, emergency events, EOP, dispatch,
  emergency resource units, SITREP, AAR, live hazard SSE, the command centre
  and the public hazard/emergency map.
- Documented the public boundary as `https://sos.synapsecity.sbs`.
- Represented responders as `sos-resource-units`; removed the City user model
  and any `/v1/users` dependency.
- Updated `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, the new
  `PRODUCT_BOUNDARY.md` and the console documentation to describe the split.

### Removed

- Foreign City console routes and pages under `/admin/assets*`,
  `/admin/incidents*`, `/admin/iot*`, `/admin/budgets*`, `/admin/reports*`,
  `/admin/alerts*`, `/admin/ingest`, `/admin/users*`, `/technician*`,
  `/asset/$id`, `/public/report*`, `/public/incidents*` and `/disaster`.
- City API handlers, service modules, client functions, types and navigation
  entries from the SOS gateway, service and console.
- City datasets and seeds from the SOS configuration.

### Added

- Gateway guards that return `404` with `{ "error": "not_found" }` for foreign
  city `/v1` namespaces before any upstream call.
- Service start-up guard and tests that reject any dataset without the `sos-`
  prefix.
- `GET /v1/sos` feature metadata that advertises owned SOS features and lists
  the City features as not owned.
- `/v1/auth/*` stateless HMAC session shell (login, register, refresh, logout,
  change-password, me, verify) with optional `AUTH_SECRET`; no password or user
  dataset is created.
- `requireSession` protection for internal emergency and hazard routes while
  keeping the public emergency projection, hazard reads, stream, map, geo and AI
  routes open.
- `POST /v1/hazards/expire-stale` with a configurable TTL (default 24 hours).

### Fixed

- Hazard SSE frames now use real LF newlines (`event: hazards\ndata: ...\n\n`),
  so `EventSource` dispatches the `hazards` event. A raw-byte regression test
  covers the stream.
- Hazard deploy returns `hazard_id`, `event_id`, `eop_plan_id` and
  `markdown_body` alongside the legacy nested `hazard`/`event`/`eop_plan`
  objects, so the EOP modal can save and submit drafts.
- Dispatch approval normalizes `assigned_resource_unit_id` (accepting legacy
  `resource_unit_id`/`assigned_user_id`) and mirrors the same resource-unit id
  into `assignments[]`; the rescue page resolves the canonical field.
- The console normalizes non-array 200 responses (`asList`) so the command
  centre and hazard map show an empty/error state instead of crashing on HTML.
- Encoded `/%76%31/...` API paths are decoded and proxied to the canonical
  `/v1` route (or rejected with JSON 404); they never return the console SPA.
- Regenerated `apps/console/package-lock.json` so `npm ci` and
  `docker compose build` succeed, and added `apps/console/.dockerignore`.
- SOS PWA manifest and service-worker cache now use SynapseCity SOS branding
  instead of `OpenInfra`.
- SOS API docs list the implemented auth endpoints, mark Bearer-protected
  routes and use `https://sos.synapsecity.sbs` only.
